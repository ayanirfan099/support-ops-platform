## Screenshot provenance

The committed images in `docs/screenshots/` are generated by `apps/web/e2e/capture-screenshots.spec.ts`.

The capture:

1. signs into a fictional seeded owner account;
2. creates a fictional duplicate-billing ticket;
3. adds a fictional billing playbook;
4. performs line-cited lexical search;
5. requests a local triage suggestion;
6. records an explicit human billing-queue decision;
7. captures the dashboard, evidence search and reviewed triage UI.

The capture test is skipped in ordinary CI unless `CAPTURE_PORTFOLIO_SCREENSHOTS=1` is set. This prevents routine CI from rewriting tracked binary files.

## Reproduce the main verification

From the repository root with safe local environment variables configured:

    pnpm install --frozen-lockfile
    pnpm db:generate
    pnpm --filter @supportops/database prisma:deploy
    pnpm db:seed
    pnpm db:seed
    pnpm format:check
    pnpm lint
    pnpm typecheck
    pnpm test
    pnpm test:integration
    pnpm build
    pnpm test:e2e

From `services/intelligence`:

    uv sync --locked --all-extras
    uv run --locked ruff format --check .
    uv run --locked ruff check .
    uv run --locked pytest -q

Dependency/security checks:

    pnpm audit --audit-level low
    uv export --locked --all-extras --no-emit-project       --format requirements-txt --output-file /tmp/supportops-requirements.txt
    uvx --from pip-audit==2.10.1 pip-audit       --requirement /tmp/supportops-requirements.txt
    gitleaks git --config .gitleaks.toml --redact --log-opts=--all .

## Repository security controls reviewed

Observed on 2026-11-03:

- GitHub Actions default token permission is `read`.
- Workflows cannot approve pull-request reviews.
- CI explicitly uses `contents: read`.
- JavaScript and Python dependency audits run in CI.
- Gitleaks scans full Git history.
- The hardening branch adds weekly Dependabot updates for pnpm, uv, GitHub Actions and both Dockerfiles.
- Main branch protection was not accessible/configured through the inspected endpoint.
- Dependabot and code-scanning alert APIs were not enabled or were not accessible; secret-scanning alert access was inconclusive from the local CLI environment.

Recommended main-branch rule:

- require pull requests;
- require conversation resolution;
- require `quality`, `Dependency and secret scans`, and `Container build and smoke test`;
- block force pushes and branch deletion;
- do not allow status-check bypass for routine changes.

Apply repository rules only after confirming that the account plan and GitHub UI expose the intended settings.

## Known limits and non-claims

- No public deployment, real users, real customer data, benchmark, load test, independent security audit or accessibility certification is claimed.
- Email verification/delivery, password recovery, production registration controls, production secrets, backups, monitoring and incident response remain deployment gates.
- PDF/file upload, OCR, external model providers and customer email delivery are intentionally out of scope.
- The classifier is a deterministic synthetic-fixture baseline with abstention; its scores are not calibrated probabilities.
- The retrieval ranker is lexical and bounded; citations expose source excerpts but do not prove answer correctness.
